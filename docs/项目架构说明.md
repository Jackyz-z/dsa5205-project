# 项目架构说明

## 1. 项目做什么

每天收盘后，模型预测 SPY 下一持有期的超额收益，再由一条固定规则转换成 SPY 仓位（0–150%），其余资金持有现金。

```text
第 t 日收盘        第 t+1 日开盘        第 t+2 日开盘
    │                  │                    │
 决策：计算特征      成交：调到目标仓位     标签实现，
 和预测                                    再按新预测调仓
                       └── 这段收益就是标签 ──┘
```

| 项目 | 设定 |
|---|---|
| 交易资产 | SPY 和现金 |
| 基准 | SPY 买入持有、历史均值预测、AR(1) 预测 |
| 数据来源 | Yahoo Finance（`yfinance`）：SPY、^VIX、^TNX、^IRX |
| 候选模型 | 岭回归（Ridge）；测试锁定后加入 LASSO 作探索性比较 |

## 2. 整体架构

核心原则：**模型只负责“输入特征、输出预测”，不知道成本和仓位规则；策略和评测只读预测文件，不知道预测来自哪个模型。**

```text
Yahoo Finance
     │
     ▼
┌──────────────────┐  下载、检查、计算特征和标签
│ 数据层 data/      │
└────────┬─────────┘
         │ data/processed/dataset.csv
         ▼
┌──────────────────┐  切窗口、排除未实现标签、标准化
│ 滚动引擎 engine/  │◄──────────┐
└────────┬─────────┘           │ 只调用 fit(X, y) 和 predict(X)
         │                ┌────┴─────────┐
         │                │ 模型层 models/ │
         │                └──────────────┘
         │ results/<阶段>/<模型>/<配置>/predictions.csv
         ▼
┌──────────────────┐  预测 → 仓位 → 扣费后收益（所有模型同一规则）
│ 策略层 strategy/  │
└────────┬─────────┘
         ▼
┌──────────────────┐  指标、图表、表格
│ 评测层 evaluation/│
└──────────────────┘
```

`pipeline.py` 负责串联这些层，并管理测试集锁；`cli.py` 提供命令行入口。

## 3. 环境与运行

需要 Python 3.11 或更高版本。在项目根目录执行：

```bash
# 如果 python3 -m venv 报 ensurepip 错误，改用 uv，见 README
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python -m timing.cli data                   # 1. 下载数据并构建数据集
python -m timing.cli validate --model all   # 2. 跑验证集并选模型
python -m timing.cli report                 # 3. 生成验证集表格和图表
pytest                                      # 运行全部测试
```

**以下命令会使用测试集。全组确认冻结所有模型之前，不要运行：**

```bash
python -m timing.cli test --confirm-final   # 4. 只跑一次
python -m timing.cli report                 # 5. 生成测试集表格和图表
```

## 4. 各层说明

### 4.1 数据层

`dataset.csv` 是数据层对外的唯一接口，每个决策日 t 一行：

| 列 | 含义 | 何时已知 |
|---|---|---|
| `f_*` | 14 个特征 | 第 t 日收盘 |
| `b_lag_y` | 第 t−1 日开盘到第 t 日开盘的超额收益，只给 AR(1) 用 | 第 t 日开盘 |
| `spy_ret` | 第 t+1 日开盘到第 t+2 日开盘的 SPY 收益 | 第 t+2 日开盘 |
| `rf_ret` | 同期现金收益：^IRX ÷ 100 × 日历天数 ÷ 360 | 利率在第 t 日已知 |
| `y` | 训练标签：`spy_ret − rf_ret` | 第 t+2 日开盘 |
| `entry_date` | 第 t+1 日，成交日 | — |
| `label_end` | 第 t+2 日，标签实现日 | — |

**14 个特征：**

| 特征 | 定义 | 回看窗口 | 为什么可能有用 |
|---|---|---|---|
| `f_overnight` | 今日开盘 ÷ 昨日收盘 − 1 | 1 日 | 隔夜信息和反转 |
| `f_intraday` | 今日收盘 ÷ 今日开盘 − 1 | 当日 | 日内压力和反转 |
| `f_ret_5` / `f_ret_21` / `f_ret_63` | 收盘价收益 | 5、21、63 日 | 短期反转或延续 |
| `f_mom_252` | 收盘价收益 | 252 日 | 长期动量 |
| `f_ma200_gap` | 收盘价相对 200 日均线的偏离 | 200 日 | 趋势状态 |
| `f_rv_21` | 日收益标准差年化 | 21 日 | 风险水平 |
| `f_volume_ratio` | 成交量 5 日均值 ÷ 63 日均值 | 5、63 日 | 交易拥挤程度 |
| `f_vix_log` | VIX 的对数 | 当日 | 隐含风险 |
| `f_vix_chg_5` | VIX 对数的变化 | 5 日 | 恐慌变化 |
| `f_vix_minus_rv` | VIX ÷ 100 − 已实现波动率 | 21 日 | 风险溢价代理 |
| `f_term_spread` | ^TNX − ^IRX | 当日 | 期限结构 |
| `f_long_rate_chg_5` | ^TNX 的变化 | 5 日 | 利率冲击 |

**清洗规则：**
- 以 SPY 交易日历为准。利率缺失时只向前填充最近已知值，最多 5 天；实际有 21 个缺失交易日，都记录在 `manifest.json` 中。
- 特征预热期内有缺失值的行直接删除，所以数据集从 1994-01-27 开始。
- 极端值不在数据层处理，而是在标准化后截断到 ±5。

### 4.2 模型层

每个模型都继承 `BaseModel`，只需实现两个方法：

```python
fit(X: pd.DataFrame, y: pd.Series) -> self
predict(X: pd.DataFrame) -> np.ndarray   # 一维，每行一个预测
```

还可以选择实现 `diagnostics()`，返回系数等信息；引擎会把它保存到 `diagnostics.csv`。

**岭回归的目标函数：**

```text
(1/T) Σ(y − a − Xβ)² + λ‖β‖²
```

- 按窗口长度 T 归一化，因此不同窗口的 λ 含义可比。
- 截距不受惩罚，λ 越大，预测越接近窗口内的平均收益，也就是历史均值基线。

模型的 YAML 配置：

| 字段 | 含义 |
|---|---|
| `name` | 注册名，必须与文件名和 `@register` 一致 |
| `role` | `candidate` 可被选为最终模型；`baseline` 只作对比 |
| `feature_set` | 特征组，定义在 `features.py` 的 `FEATURE_SETS` 中 |
| `preprocess` | `standard` 标准化，`none` 不处理 |
| `grid` | 超参数网格，必须包含 `window` |

### 4.3 滚动引擎

对网格中的每个配置，`rolling.py` 这样运行：

1. 从 1999 年开始，每 21 个交易日重新拟合一次。
2. 在拟合日 t，只取 `label_end ≤ t` 的样本，再取最近 `window` 行。第 t−1 和第 t 日的标签还不知道，所以会被排除。
3. 只用训练窗口拟合标准化参数。
4. 用这个模型预测接下来 21 个交易日，直到下次拟合。

如果已实现标签不足一个完整窗口，就跳过这次拟合。

### 4.4 时间划分

| 阶段 | 决策日期 | 作用 |
|---|---|---|
| 特征预热和首个训练窗口 | 1993-01-29 至 1998 年 | 计算特征，开始训练 |
| 预测预热 | 1999-01 至 2000-02 | 积累仓位公式需要的预测历史，不计入成绩 |
| 验证 | 2000-03-01 至 2010-12-31 | 选超参数 |
| 测试 | 2011-01-01 至 2026-10-30 | 只跑一次 |

一行要属于某个阶段，它的整个持有期都必须在该阶段内。验证流程在运行前会删除 `label_end` 晚于验证期末的所有行，所以读不到测试期数据。

### 4.5 策略层

所有模型共用同一条规则，参数在 `base.yaml` 中固定：

```text
z = (今日预测 − 过去 252 日预测均值) ÷ 过去 252 日预测标准差
目标仓位 = 1 + 0.5 × z，限制在 0–1.5
```

**回测逻辑：**
1. 先算出价格变动后的实际仓位。
2. 与目标相差超过 10 个百分点才调仓，否则不动。
3. 净收益 = `w × spy_ret + (1 − w) × rf_ret − 调仓量 × 成本`。

**假设和简化：**
- 成本 5 bps 是我们的假设，报告中同时给出 0、1、2、5、10 bps 的敏感性。
- 杠杆部分按 ^IRX 融资，比实际融资成本偏乐观。
- 仓位不到调仓阈值时可能因价格波动略微超过 150%。
- 复权开盘价已包含分红，所以开盘到开盘的收益反映了分红。

### 4.6 评测层

| 类型 | 内容 |
|---|---|
| 预测 | 样本外 R²（相对同窗口历史均值）、方向准确率 |
| 交易 | 扣费后年化收益、波动率、Sharpe 及其近似标准误、最大回撤、换手率、平均仓位 |
| 风险调整 | 相对 SPY 的 CAPM alpha 和 beta（Newey-West 标准误，5 阶滞后） |

**选择规则：** 候选模型中，验证期扣除 5 bps 成本后 Sharpe 最高者为最终模型。

输出在 `results/` 下：

| 路径 | 内容 |
|---|---|
| `validation/<模型>/<配置>/predictions.csv` | 每日预测 |
| `validation/<模型>/grid_metrics.csv` | 该模型全部网格的结果 |
| `validation/selection.json` | 选择结果 |
| `tables/<阶段>/` | `summary`、`subperiods`、`yearly`、`cost_sensitivity` 四张表 |
| `figures/<阶段>/` | 累计收益、累计 R²、分时期、成本敏感性、仓位、系数图 |
| `figures/validation/grid_<模型>.png` | 网格热力图（模型除窗口外只有一个超参数时生成） |
| `experiment_log.csv` | 每次运行的记录，报告中要用它说明试过多少模型 |

## 5. 如何新增模型

以 LASSO 为例，**只需新增两个文件，不用改其他代码**。我们已在独立副本里实际走过这个流程。

**第一步：`timing/models/lasso.py`**

```python
from sklearn.linear_model import Lasso

from timing.models.base import BaseModel
from timing.models.registry import register


@register("lasso")
class LassoModel(BaseModel):
    def __init__(self, alpha, seed=0):
        super().__init__(seed)
        self.alpha = alpha

    def fit(self, X, y):
        self._model = Lasso(alpha=self.alpha, random_state=self.seed)
        self._model.fit(X.to_numpy(), y.to_numpy())
        return self

    def predict(self, X):
        return self._model.predict(X.to_numpy())
```

**第二步：`configs/models/lasso.yaml`**

```yaml
name: lasso
role: candidate
feature_set: core
preprocess: standard
grid:
  window: [252, 1260]
  alpha: [0.000001, 0.00001, 0.0001, 0.001]
```

**第三步：检查并运行**

```bash
pytest tests/test_models.py                 # 自动检查接口、可复现性和防泄露
python -m timing.cli validate --model lasso
python -m timing.cli report
```

**注意事项：**
- 模型内部如需验证集（如早停），必须在传入的 `X`、`y` 里按时间切分。
- 带随机性的模型要使用 `self.seed`，否则可复现性测试会失败。
- 树模型通常可以设 `preprocess: none`。
- 新特征加到 `features.py`，并放进 `FEATURE_SETS` 的一个新特征组。不要改动 `core` 组，否则之前的结果会失效。
- 第一版只支持每天一行的表格输入。LSTM 等序列模型需要先扩展引擎的输入格式。
- 网格要小而且事先定好；试过的每个配置都会写进实验日志。

## 6. 防泄露与测试集纪律

| 风险 | 控制方法 | 对应测试 |
|---|---|---|
| 特征用到未来数据 | 特征只用当日及以前的数据 | 截断未来数据后，历史特征完全不变 |
| 用未实现的标签训练 | 按 `label_end ≤ 拟合日` 筛选 | 检查每次拟合的训练集 |
| 模型读到未来 | 引擎只传训练窗口和待预测特征 | 篡改未来数据后，历史预测不变（每个模型都测） |
| 标准化泄露 | 只在训练窗口拟合 | 预处理单元测试 |
| 验证集读到测试期 | 运行前删除测试期的行 | 篡改测试期数据后，验证结果不变 |
| 收盘价信号在同一收盘成交 | 下一开盘成交，标签为开盘到开盘 | 手算核对标签 |
| 回测计算错误 | 仓位漂移、现金、杠杆和成本分开处理 | 手算核对回测 |

**测试集锁的规则：**

| 情况 | 行为 |
|---|---|
| 没有 `--confirm-final` | 拒绝运行 |
| 首次确认运行 | 写入 `results/test/lock.json`，记录配置和选择结果的哈希值 |
| 配置和选择都未改动，再次运行 | 允许，视为复现 |
| 配置或选择改动过 | 拒绝运行 |
| 锁定后新增的模型 | 只能用 `test --exploratory <模型>`，结果放在 `results/test_exploratory/`，不参与最终选择 |

`lock.json` 要随代码一起提交，这样才能证明测试只用过一次。助教从零运行时，如果选择结果相同，就会被视为复现。

## 7. 目前的验证集结果

以下数据来自 2000-03-01 至 2010-12-29，成本 5 bps。**这些是验证集结果，不能作为样本外结论。**

| 模型 | 年化收益 | 年化波动 | Sharpe | 最大回撤 | 年化换手 | 样本外 R² |
|---|---|---|---|---|---|---|
| Ridge（λ=100，窗口 1260，被选中） | 7.75% | 16.76% | 0.38 | −32.7% | 17.0 倍 | 0.01% |
| LASSO（α=0.001，窗口 1260） | 4.87% | 21.22% | 0.22 | −46.1% | 17.4 倍 | −0.03% |
| 历史均值（窗口 1260） | 7.57% | 14.68% | 0.40 | −23.8% | 2.5 倍 | 0 |
| AR(1)（窗口 1260） | −1.57% | 23.51% | −0.05 | −57.7% | 101.7 倍 | −0.29% |
| SPY 买入持有 | 0.88% | 21.94% | 0.04 | −55.4% | 0 | — |

Ridge 全部 10 个配置的 Sharpe（`results/validation/ridge/grid_metrics.csv`）：

| 窗口 \ λ | 0.01 | 0.1 | 1 | 10 | 100 |
|---|---|---|---|---|---|
| 252 | 0.01 | 0.07 | 0.09 | 0.04 | −0.03 |
| 1260 | 0.07 | 0.10 | 0.08 | 0.09 | **0.38** |

### 需要全组注意的问题

**这个结果不能理解为“特征有效”。** 我们单独拆开检验后发现：

- 选中的配置位于网格边缘（最大的 λ），系数几乎被压没了。它的预测中，来自均值的波动（标准差 2.5e-4）约为来自特征的波动（4.8e-5）的 5 倍。
- 它的仓位与历史均值基线的相关系数为 0.93，而且扣费后 Sharpe 还略低于基线。
- 抽查 5 个配置，只用特征部分构造仓位时，Sharpe 在 0.06（窗口 1260、λ=100）到 0.16（窗口 252、λ=100）之间，而标准误约 0.30，无法与零区分。这项拆解是一次性分析，目前不在管线里。

**0.38 这个 Sharpe 主要来自哪里？** 历史均值策略本身就会择时：滚动平均收益上升时加仓、下降时减仓，效果接近慢速趋势跟随。2000–2010 年有两次大熊市，这类规则很占优，但换一个时期未必成立。

因此方案中“历史均值基线基本等同于持有 SPY”的说法是**错误的**：只有预测完全不变时才成立。

### 冻结前需要决定

这些问题可以在验证阶段调整，但必须在运行测试集之前决定：

1. **仓位规则：** 保持现状，还是只用去掉均值后的特征部分（`预测 − 同窗口历史均值`）来计算 z？后者更能检验特征本身，但需要修改 `strategy/`，并把这次修改如实写进报告。
2. **网格范围：** 最优值落在边缘，是否要在冻结前把 λ 往更大或更细的方向扩展？这有助于确认结果是否稳定，但也增加了试过的模型数量。
3. **其他模型：** LASSO 在测试锁定后接入，因此只参与验证比较；其测试期结果放在
   `results/test_exploratory/lasso/`，不参与正式模型选择。

| 附录公式 `1/(1 + D/P_{t−1})` | 5.4e-7 | 6.4e-5 |
| 减法公式 `1 − D/P_{t−1}` | 2.1e-7 | 1.3e-6 |

减法公式更接近 Yahoo，但仍未达到机器精度。另外，附录中称其公式可使总收益“正好成立”，严格来说只是近似；要精确成立，因子需要用 `1/(1 + D/P_t)`。报告中可以简要说明这一点。

## 9. 复现性

- **随机种子：** 固定为 42。Ridge 和两个基线都是确定性模型。
- **依赖版本：** 固定在 `requirements.txt` 中。
- **路径：** 全部相对于项目根目录，已在一个没有 `data/` 和 `results/` 的干净目录中按 README 跑通数据到验证报告。
- **系统兼容性：**
  - 已在 Ubuntu 24.04（WSL2）和 Python 3.12 上实际运行。
  - macOS 没有实际运行过；只确认了依赖在 Apple 芯片和 Intel 的 Mac 上都有预编译包，代码也没有用系统专属功能。建议有 Mac 的组员跑一次 `pytest`。
- **Yahoo 数据的波动：** 同一天两次下载的 SPY 复权价相对差异最大约 1.5e-6，导致 `data_hash` 不同，一个 Sharpe 变化了 0.0001，选中的模型不变。Yahoo 也可能修订历史，所以以后下载的差异可能更大。
